# Lumen 기능 안내서

Lumen는 **방어적인** 시스템 진단 도구입니다. 코드를 읽고, 모듈 사이의 업무적 결합과 인과 관계를 정리하고, 생길 수 있는 버그를 예측하며, 수정 제안과 검증 보고서를 내놓습니다. **어떤 시스템도 공격하지 않습니다.** 오직 여러분의 프로젝트만 살펴봅니다.

## 1. 시작하기

- **처음 실행할 때**: 설정 마법사가 언어, 코드 폴더, 프로젝트 이름, AI 서비스, 협업 방식을 고르도록 도와주고 프로젝트를 만듭니다.
- **그 다음부터**: 열 프로젝트를 고르거나, 새로 만들거나, 기존 설정 파일을 엽니다. 프로젝트마다 설정, 조사 기록, 장기 기억, 결합 그래프가 따로 있습니다.
- **프로젝트 바꾸기**: 왼쪽 위의 프로젝트 이름을 누릅니다.

## 2. 조사 시작하기

홈 화면 입력창에 “재접속 후 코인이 두 번 지급될 수 있나요?”처럼 자기 말로 문제를 쓰고 Enter를 누릅니다. 입력창 아래에서 누가 맡을지 고릅니다(3절 참고).

조사 화면에는 읽은 파일, 검색한 내용, 얻은 결론 등 모든 단계가 실시간으로 보입니다. 최종 답변은 증거를 제시하고, 확인된 것과 추측일 뿐인 것, 다루지 못한 것을 구분해서 알려 줍니다. 이어서 질문할 수도 있습니다.

## 3. 네 가지 협업 방식

| 방식 | 구성 | 알맞은 경우 |
|---|---|---|
| 단독 어시스턴트 | 에이전트 1명이 직접 조사 | 단일 버그, 빠른 점검. 비용이 가장 적음 |
| 2인 상호 검토 | 실행자 1명 + 감독자 1명 | 다른 사람의 확인이 필요한 문제 |
| 협업 팀 | 리더 2명 + 실행자, 실행자 2명당 감독자 1명 | 여러 모듈에 걸친 문제 |
| 듀얼 헤드 클러스터 | 리더 2명 + 최대 19쌍의 실행자·감독자 | 시스템 전체의 결합과 인과. 최대 40명 |

- **논리 리더**는 결합과 근본 원인을 분석하고 각 이상을 어떻게 처리할지 정합니다. **배분 리더**는 일을 나누어 맡기고, 보고를 검토하고, 전달을 승인합니다.
- **실행자**는 코드를 읽고 허용된 명령을 실행하며 결론을 제출합니다. **감독자**는 모든 결론을 독립적으로 다시 확인하고 반례를 찾습니다.
- 일이 없는 에이전트는 모델을 부르지 않으며 비용도 들지 않습니다. 각 에이전트의 모델은 전적으로 여러분이 정합니다.

협업 방식과 인원은 ‘설정 → 클러스터 → 협업 방식’에서 바꿉니다. 저장하고 다시 시작하면 적용됩니다.

## 4. 증거와 결론

- 모든 결론은 도구가 돌려준 증거(파일과 줄 번호, 명령 출력 등)를 인용해야 하며, 지어낸 증거는 거부됩니다.
- 결론의 상태는 **검증 전**, **확정**(감독자가 독립적으로 재확인), **반박됨**, 재검토 필요 등입니다. 사실로 인정되는 것은 ‘확정’뿐입니다.
- 모든 결론은 ‘설정 → 저장소 → 결론과 기억’에서 검색할 수 있습니다.

## 5. 빠짐없는 이상 보고와 리더의 결정

- 에이전트가 발견한 모든 이상 — 충돌, 가끔 일어나는 실패, 눌리지 않는 버튼, 빠진 픽셀 하나, 어긋난 글자, 로그의 이상한 경고, 의심되는 결합 — 은 **이상 수신함**에 들어가며 지워지지 않습니다. 같은 이상은 하나로 합치고 매번의 증거를 남깁니다.
- 심각한 이상은 바로 리더를 깨우고, 작은 것도 다음 검토 때 반드시 다뤄집니다.
- 논리 리더는 먼저 다섯 가지 ‘미세 이상’ 질문에 답한 뒤 **즉시 수정 / 조사 확대 / 보류 / 확인 필요** 중 하나를 정합니다. 우선순위는 모델이 아니라 프로그램이 ‘겉보기 크기 × 결합 영향의 깊이’로 계산합니다.
- 재확인은 다른 실행자에게 맡겨 처음 판단에 기대지 않습니다.

## 6. 쉽게 ‘완료’라고 하지 못하게

리더는 **미해결 문제 목록**을 계속 유지합니다. 하위 작업이 진행 중이거나, 결정되지 않은 이상이 있거나, 확인되지 않은 항목이 있으면 시스템이 리더를 다시 작업으로 돌려보냅니다. 최종 답변 끝에는 시스템이 집계한 **세부 점검 목록**(업무 흐름, 모듈 간 결합, 화면 요소, 화면 크기, 네트워크 끊김·종료·동시 실행, 장시간 동작)이 붙습니다. 감독자가 재확인한 결론만 항목에 체크할 수 있습니다.

## 7. 결합 그래프

‘설정 → 저장소 → 결합 그래프’는 함수, 엔드포인트, 이벤트, 네트워크 메시지, 상태, 테이블의 관계를 그립니다. 변경이 어디에 영향을 주는지, 여러 증상의 공통 원인, 구조적 위험(같은 데이터를 쓰는 입구가 여럿이거나 재시도가 두 번 쓰는 경우 등)을 볼 수 있습니다.

## 8. 장기 기억

에이전트는 남길 만한 사실(경로, 줄 번호, 버전, 조건, 원인, 증거)을 메모로 저장하고 다음 조사에서 관련된 것을 떠올립니다. ‘설정 → 장기 기억’에서 임베딩 모델을 고르면 표현이 다른 예전 결론도 떠올립니다. 모든 기록은 이 컴퓨터에 저장되며, 컨텍스트를 압축해도 원래 기록은 사라지지 않습니다.

## 9. 작업 공간 개요

조사 화면 오른쪽 가장자리에 세로로 된 ‘작업 공간 개요’ 탭이 있습니다. 열면 **바뀐 파일**(줄 단위 차이), 에이전트별 **타임라인**, **읽은 파일**, **실행한 명령과 컴퓨터 조작**, **결론과 기억**을 볼 수 있습니다.

## 10. 컴퓨터 조작(기본은 꺼짐)

켜면 에이전트가 화면 캡처, 마우스 이동, 클릭, 입력, 지정한 프로그램 열기·닫기, 터미널 명령 실행을 할 수 있습니다. 안전 규칙:

- 지정한 창만 쓸 수 있고, 프로그램이 모든 조작을 먼저 검사합니다.
- 영향이 있는 조작은 먼저 감독자의 승인이 필요하고, 삭제·전송·결제 같은 **되돌릴 수 없는 조작은 여러분의 승인도 필요**하며 승인은 앱 안에서만 할 수 있습니다.
- **비상 정지**: 창 위쪽의 ‘지금 정지’ 버튼, `Ctrl+Alt+End`, 또는 마우스를 화면 왼쪽 위 모서리로 밀기.

## 11. 지속 모니터링(선택)

협업 팀이나 듀얼 헤드 클러스터에서 켜면 두 리더가 쉬는 동안 앞으로 생길 버그를 예측합니다. 정한 빈도와 토큰 예산에 따라 모델을 부릅니다.

## 12. 설정 한눈에 보기

- **저장소**: 결합 그래프, 이상 수신함, 결론과 기억.
- **클러스터**: 에이전트 클러스터(실시간 상태, 에이전트를 누르면 자세히), 협업 방식.
- **설정**: 서비스와 키, 에이전트 모델, 장기 기억, 컴퓨터 조작, 모양(배경, 시작 애니메이션, 움직임, 화면 언어).

바꾼 뒤에는 오른쪽 아래 **저장**을 누르세요. ‘변경 취소’나 저장하지 않고 닫으면 아무것도 남지 않습니다.

## 13. 보안과 개인정보

- 모델은 모두 여러분이 고르며, Lumen가 스스로 모델을 바꾸지 않습니다.
- API 키는 이 컴퓨터의 Windows 자격 증명 관리자에만 보관되고, 저장을 누를 때 기록되며 언제든 지울 수 있습니다.
- 코드에는 민감도(공개, 내부, 기밀, 극비, 로컬 전용)가 있고, 그 민감도를 받을 수 없는 모델 서비스에는 내용이 가지 않습니다.
- 모든 로그, 증거, 기억은 여러분의 컴퓨터에 남습니다.

## 14. 팁

- 앱이 갑자기 닫히면 `~/.codedoctor/crash.log`를 개발자에게 보내 주세요.
- 비용을 아끼려면 단독 어시스턴트, 여러 모듈에 걸친 문제라면 클러스터를 쓰세요.
- 감독자에게 실행자와 다른 모델을 주면 재확인이 더 믿을 만해집니다.

## 15. 코드 수정과 자동 테스트

설정 → 코드 수정과 테스트 에서 「에이전트가 프로젝트 파일을 직접 수정」을 켜면 Lumen가 진단뿐 아니라 수정까지 합니다. 실행자는 보고서 없이 수정만 하고, 감독자가 모든 변경을 확인하고 직접 테스트를 다시 돌려 보고합니다. 테스트 명령을 설정하면 시스템이 변경 전후마다 테스트를 돌리고(모델·토큰 없이), 전에 통과하던 테스트가 깨지면 바로 알려 줍니다. 먼저 git에 커밋해 두세요.

## 16. Lumen 팀

대화 상대는 Lumen뿐입니다. 전문 작업은 멤버에게 맡깁니다. Spark는 코드, Prism은 점검, Torch는 실전 테스트, Ray는 검색, Lantern은 파일, Beacon은 감독, Iris는 컴퓨터 조작을 맡습니다. 멤버마다 자기 기억이 있고 일회용 도우미도 부를 수 있습니다.

## 17. 오른쪽 패널

왼쪽 레일의 지구본과 터미널 아이콘을 누르면 채팅 옆에 패널이 열립니다.

- **브라우저**: 시작 페이지는 검색창 하나이며 그 자리에서 검색합니다. 채팅의 링크도 여기서 열립니다. 검색 엔진은 모양 설정에서 고릅니다.
- **터미널**: 프로젝트 폴더에서 실행되는 진짜 PowerShell입니다. 팀이 실행한 명령도 여기에 표시됩니다. Ctrl+C로 실행 중인 것을 멈춥니다.

## 18. Code3D로 3D 만들기

@Code3D를 입력하고 원하는 것을 말하세요. 팀이 컴퓨터의 Blender용 코드를 쓰고 그림을 보며 고친 뒤, 완성 그림을 채팅에 보여 줍니다. 아무도 보지 않은 버전은 내보낼 수 없습니다.

## 19. 여러 창

한 폴더를 여러 창에서 열 수 있습니다(Ctrl+Shift+N). 창마다 채팅이 따로 있습니다.

## 20. 작지만 편한 기능

- **Ctrl+K**: 대화, 페이지, 작업을 한 칸에서 찾습니다. 두 글자 이상이면 대화 내용까지 검색합니다. Ctrl+/ 는 모든 단축키를 보여 줍니다.
- **대화 우클릭**: 이름 바꾸기, Markdown으로 내보내기, 치워 두기. 삭제되지 않으며 Ctrl+K의 "치워 둔 대화 되돌리기"로 돌아옵니다.
- **답변 아래**: 복사, 기억하기(프로젝트 장기 기억에 저장), 다시 답하기, 고쳐서 다시 묻기. 코드 블록을 우클릭하면 코드만 복사합니다.
- **Ctrl+F**: 답변 안에서 찾습니다.
- **입력창**: 파일을 끌어다 놓거나 붙여 넣을 수 있습니다. Ctrl+S로 문구를 저장하고 빈 입력창에서 / 로 불러옵니다. 보내지 않은 글은 창을 닫아도 남습니다.
- **완료 알림**: 창이 앞에 없으면 작업 표시줄이 빛나고 알림이 뜹니다. 클릭하면 그 대화로 갑니다. 모양에서 끌 수 있습니다.
- **사용량**: 설정의 사용량 페이지에서 오늘, 7일, 전체를 봅니다. 하루 한 막대이고 새 토큰과 캐시는 따로 셉니다.
- **브라우저**: 별로 페이지 저장, 리본으로 즐겨찾기, Ctrl+Shift+T로 닫은 탭 복구, 말풍선으로 페이지를 Lumen에 보냅니다.
- **터미널**: 출력을 우클릭해 선택한 부분이나 최근 출력을 Lumen에 보냅니다.

## 21. 더 많은 제작 도구

입력란에 @를 입력하면 이 도구들을 부를 수 있습니다. Code3D처럼 AI가 쓰고, 스스로 확인하고, 고칩니다:

- **@CodeSound**: 음악과 효과음. 모두 이 컴퓨터에서 합성합니다. AI는 들을 수 없어 소리를 측정해 그림으로 그립니다. 듣기 좋은지는 사용자가 판단합니다.
- **@CodePage**: 웹페이지. CodePage를 직접 열어 구성 요소를 끌어다 놓을 수도 있습니다. 코드는 자동으로 만들어지며 무료입니다.
- **@CodeGame**: 플레이 가능한 3D 게임. 웹 파일 하나로 만들고 AI가 직접 해 봅니다.
- **@CodeDeck**: 슬라이드와 문서: PowerPoint, Word, PDF.
- **@CodeData**: Excel과 CSV를 분석합니다. 보고서의 모든 숫자는 출처를 확인할 수 있습니다.
- **@CodeCAD**: 3D 프린트용 부품. 치수를 실측합니다. Blender가 필요합니다.
- **@CodeLab**: 학습 로그를 읽습니다. 실행 중인 작업은 건드리지 않습니다.

## 22. 플러그인

왼쪽의 플러그인을 누르면 모든 도구가 보입니다. 클릭하면 열리고, 위의 칸에서 찾을 수 있습니다.

CodeTools에는 로고, 애니메이션, 도표, QR 코드, 전자책, 자막, 음성, 이미지 일괄 처리, PDF, 파일 정리, 백업, 전문 검색, API 테스트, 데이터베이스, 로그 분석, 계산, 회로, 물리, 일정, 지도, 게임 밸런스, 짧은 영상 등 수십 가지 작은 도구가 있습니다. @CodeTools를 입력하면 AI도 쓸 수 있습니다.
- **@CodeFilm**: 한 문장으로 짧은 영상. 콘티, Code3D 장면, CodeSound 음악, Windows 음성, 자막까지.
