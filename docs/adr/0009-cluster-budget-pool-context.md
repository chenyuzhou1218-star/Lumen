# ADR 0009：多 Agent 集群加强——共享预算、执行者池、带上下文分派、监督者独立性提醒

- 状态：提议（待审查）
- 日期：2026-10-25
- 作者：Claude
- 用户要求：上下文优化之后加强多 Agent 集群。
- 承接：[ADR 0005](0005-coupling-graph-and-cluster.md)（集群）、[ADR 0008](0008-context-management.md)（工作记忆）

## 1. 一次调查共用一个 token 预算

**问题**：原来每个子任务各有一份预算（默认 30 万 token）。调度首脑分派 5 个子任务，再加上每个子任务的 Guardian 复查，总消耗可能是用户预期的十倍。

**决定**：

- 整棵任务树（根任务 + 所有子任务 + Guardian 复查）共用**根任务的** `max_tokens`。根任务就是用户提交的那个任务，没指定时用项目默认值。
- 用量按日志里每次模型响应的 token 数实时累计，所以正在运行的子任务也算在内。
- 预算用完后：
  - `delegate` 和 `consult` 拒绝新工作，提示"用现有结果收尾，并说明哪些没覆盖"；
  - 子任务在下一次调用模型前停止，结果为 `budget_exhausted`；
  - **根任务不会因此被停掉**，保证它总能根据已有结果给出答案。它自己的预算和步数上限仍然有效。
- 已知的超出量：每个正在运行的 Agent 最多再多用一次调用。
- `delegate` 的返回、`task_status`、调度首脑的工作记忆都会显示"已用 X / 共 Y"。

**注意，这是默认行为的变化**：一次集群调查的总预算从"每个子任务 30 万"变成"总共 30 万"。需要更多时，在项目配置的 `defaults.budget.max_tokens`，或者提交任务时的 `budget` 里调高。

## 2. 执行者池

- `delegate` 的 `agent` 参数可以写 `"any"`：交给手上未完成任务最少的执行者，平局时按配置里的顺序。这样连续分派的几个子任务会分到不同执行者，**并行**运行。
- 只决定哪个执行者接任务；每个执行者用什么模型，仍然完全由用户配置。
- `task_status` 会列出每个执行者手上的未完成任务数。

## 3. 分派时带上要核实的主张和证据

- `delegate` 新增参数 `claims`（要核实的主张 ID）和 `evidence`（起点证据 ID）。分派前会检查它们是否存在、是否完好，不存在就拒绝分派。
- 系统把这些主张的内容附在执行者的说明后面：当前状态、证据等级、作者、陈述、关系、证据 ID、证伪方法。这段内容按不可信数据隔离，因为主张的措辞来自 Agent。
- 同时说明核实的做法：
  - 成立：提交一条**新主张**，用自己拿到的证据，并把 `supersedes` 设为原主张。新主张会被这个执行者的 Guardian 复查。
  - 不成立：不要取代它，在回答里说明理由并引用证据。
- 任务消息新增 `context` 字段（`schemas/agent/message.schema.json`）。执行者的工作记忆会列出"被要求核实的主张"及其当前状态。
- 效果：逻辑首脑提出的假设，原来没有任何途径变成"已证实"。现在有了闭环：调度首脑带上假设分派给执行者，执行者用新主张取代它，Guardian 复查，新主张成为"已证实"。原假设沿取代链显示为"已证实"（M1 的取代链追踪）。

## 4. 监督者和执行者用同一个模型时提醒

- 同一个模型容易犯同样的错，用它复查效果较弱。
- 新增 `config.independence_warnings`。在桌面保存配置时，以及运行 `codedoctor check` 时，会提示哪个监督者和它监督的执行者用了同一个模型。
- **只是提醒**：不阻止保存，不自动更换模型。

## 测试

- `tests/daemon/test_cluster_upgrades.py`（4 项）：
  - 共享预算：子任务被停止、第二次分派被拒绝、根任务仍然给出答案、总用量的上限；
  - `any` 把两个子任务分给两个执行者；
  - 带主张分派：不存在的主张被拒绝；说明里有主张、证据和取代方法，并按不可信数据隔离；工作记忆显示被核实主张的状态；执行者取代原主张；Guardian 复查后新主张成为"已证实"；原主张沿取代链显示为"已证实"；
  - 同模型提醒，以及 `codedoctor check` 的输出。
- 全部 458 项通过。评测分数不变；4 次端到端运行的 token 总数从 28,321 变为 28,409（分派返回的文字变长）。

## 不在本次范围

- 用真实模型跑集群：所有验证都用脚本模型。
- 按执行者的模型能力分派任务（例如难题交给强模型）：这涉及替用户选择模型，不做。只能由用户在分派说明里指定执行者。
