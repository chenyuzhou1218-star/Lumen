# ADR 0012：电脑操作（截屏、鼠标、键盘、开关程序、终端）

- 状态：提议（待审查）
- 日期：2026-10-25
- 作者：Claude
- 用户要求：加上基础的电脑操作，也就是截屏、移动鼠标、点击、打字、按键、打开和关闭软件、终端命令，并接进多 Agent 集群。用户同意的安全方案是：默认全部关闭；有副作用的操作由监督员事前批准；不可逆操作还要用户本人批准；边界由程序硬性拦截。

## 原则：安全靠程序，监督员是第二道防线

监督员也是模型，可能被屏幕上的文字误导，也可能出错或掉线。所以：

1. **程序硬检查在前**，不经过任何模型。没通过就直接拒绝，不会去问谁。
2. **监督员事前批准**：执行者每个有副作用的操作，都要先给它配对的监督员看截图（目标位置用红圈标出）、操作内容和目的，监督员批准后才执行。监督员可以批准、拒绝，或者交给用户决定。
3. **监督员不在，就由用户来批**，绝不会在没人批准的情况下执行。以下情况都会转给用户：没有配对的监督员、监督员已暂停或停止、监督员超时（默认 180 秒）不回答、监督员结束了任务却没有给出决定。
4. **不可逆操作必须由用户本人批准**：只要执行者自己声明、监督员认定、或者程序规则判定是不可逆的，都要用户批准。
5. **执行前再检查一遍**：窗口可能已经移动，用户也可能已经按了停止。

## 配置（默认全部关闭）

```toml
[computer]
screenshot = "on"          # off | on
input = "guardian"         # 鼠标键盘：off | guardian（监督员事前批准）| ask（每次问用户）
apps = "guardian"          # 启动 / 关闭程序
terminal = "ask"           # 终端命令
windows = ["MyGame"]       # 允许看和操作的窗口（窗口标题中的文字）
launch = [{ id = "game", path = "D:/games/mygame.exe", args = ["--windowed"] }]
# capture = "windows"      # 默认只截允许的窗口；"screen" 截整个屏幕
# screenshot_data_class = "internal"   # 截图的数据级别，决定哪些模型服务能看到截图
```

- 开启鼠标键盘必须同时开启截屏：批准的人需要看到操作对象。
- 开启截屏或鼠标键盘时必须列出允许的窗口；开启"开关程序"时必须列出允许启动的程序。
- 桌面"模型与 API"页有对应设置区。

## 程序硬检查（`computer/gate.py`）

| 操作 | 检查 |
|---|---|
| 移动鼠标 / 点击 | 坐标指的是截图里的像素，由系统换算成屏幕坐标；必须在允许的窗口内，而且该位置最上层的窗口就是它（没有被别的窗口挡住）；没先截图就拒绝 |
| 打字 / 按键 | 当前在前台的必须是允许的窗口 |
| 按键 | 不允许 Windows 键；Alt+Tab、Alt+Esc、Ctrl+Esc、Ctrl+Shift+Esc、Ctrl+Alt+Del 这类会跳出窗口的快捷键直接拒绝 |
| 启动程序 | 只能启动配置里列出的程序，不经过 shell |
| 关闭程序 | 只能关闭 Code Doctor 自己启动、并且仍在运行的进程；普通关闭让程序自己决定是否提示保存 |
| 终端 | 不允许连接命令、管道、重定向、命令替换；在项目目录下运行 |
| 全部 | 对应开关必须开启；没有处于停止状态；单个任务的操作数有上限（默认 200） |

**判定为不可逆、必须由用户批准的规则**：

- 按键：Alt+F4、Shift+Delete；
- 强制关闭程序；
- 终端命令中出现删除、格式化、关机、改注册表、结束进程、`git push/reset/clean`、卸载、上传或下载类命令。

**点击的含义程序无法知道**，比如点的是"删除存档"还是"开始游戏"。这类判断交给执行者声明、监督员看截图来认定。所以把操作范围限定在用户列出的窗口很重要。

## 紧急停止

以下任一方式都会立即停止所有电脑操作，正在等待批准的操作一律拒绝：

- 窗口顶部的"立即停止"按钮；
- 全局快捷键 Ctrl+Alt+End；
- 把鼠标推到屏幕左上角（系统能区分是用户推的，还是自己刚移过去的）；
- HTTP 的 `POST /computer/stop`。

停止之后只能由用户手动恢复。

## 用户批准只能在桌面程序里进行

本地 HTTP 接口没有登录，所以它只提供查看状态和记录、停止、恢复。**批准不能通过 HTTP 进行**，否则本机任何程序都可以冒充用户批准。桌面程序和后台在同一进程里，批准是直接调用。

## 截图和隐私

- 默认只截允许的窗口。Agent 列窗口时，只能看到允许的窗口，其他窗口只告诉它数量。
- 截图缩小到 1280×800 以内，存为证据，带数据级别；不允许接收该级别的模型服务看不到截图。
- 每个截图在上下文里约按 1600 token 计算，只保留最近 2 张，更早的换成证据 ID。
- 日志只记录截图的证据 ID，不存图片本身，断点续跑时从证据库取回。
- 需要**支持图片输入的模型**，由用户选择。不支持图片的模型调用会报错，然后按原有规则停下或改用备用模型。

## 多 Agent 集群

- **执行者**（worker / investigator）和**单 Agent** 可以操作；**监督员**只能截屏、看窗口列表、做批准决定；**首脑不能操作**，即使配置里写了也会被拒绝，因为首脑只负责规划和调度。
- 批准任务在监督员的收件箱里排在最前面，执行者不会因为监督员手上有别的任务而等到超时。
- 调度首脑可以把"打开游戏复现某个问题"之类的任务分派给执行者，也可以用 `"any"` 交给最空闲的执行者。批准任务的 token 计入整次调查的共享预算。
- 执行者的任务完成后，监督员事后复查时会看到它做过的每个电脑操作：结果、目的和结果截图。
- 批准任务不写入长期记忆，否则每次点击都会留下一条记忆。
- 监督员和执行者用同一个模型时，保存配置时会提醒（ADR 0009）。

## 界面

- **窗口顶部的电脑操作栏**：显示开关状态、"立即停止 / 恢复"按钮，以及等你批准的操作卡片。卡片里有截图（红圈标出位置，点击可看原图）、操作内容、目的、为什么需要你，以及监督员的意见，可以直接批准或拒绝。
- **调查页**：显示本次调查的电脑操作记录：状态、被拦下或被拒绝的原因、结果截图。

## 局限

- 只支持 Windows。
- 这**不是沙箱**。在允许的窗口里，程序允许的操作都能做到，界面语义上的风险要靠监督员和用户把关。
- 在真实机器上**只验证了只读部分**：列窗口、截屏、读鼠标位置、坐标所在的窗口、输入事件结构大小。鼠标和键盘的真实输入还没有在用户机器上跑过。建议先用 `input = "ask"`，在记事本之类的无害窗口里试。
- 超时和取消是协作式的：操作一旦开始执行，就不能在中途打断。
- 界面上被拦下的原因是英文（给 Agent 看的那份）。

## 测试

- `tests/daemon/test_computer.py`（19 项，全部用虚拟桌面，不会动真实的鼠标键盘）：
  - 监督员批准后才点击、拒绝则不执行；
  - 不可逆操作要监督员和用户先后批准；用户拒绝则不执行；
  - 没有监督员时由用户批准；
  - 事后复查能看到电脑操作；
  - 窗口、遮挡、前台、快捷键、程序清单、自己启动的进程、终端写法等硬检查；
  - 关闭的开关；停止和恢复；鼠标推到左上角会停止；
  - 不可逆规则；只截允许的窗口，看不到其他窗口；
  - 工具随开关出现，首脑不能操作；配置校验；
  - 图片编码；上下文只保留 2 张截图，并能从日志重建；
  - 截图不会发给数据级别不够的模型服务。
- `tests/daemon/test_desktop_cluster.py`：在窗口里批准、停止和恢复，以及权限设置的保存。
- 全部 546 项通过。
