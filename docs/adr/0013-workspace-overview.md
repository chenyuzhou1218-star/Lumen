# ADR 0013：工作区一览

- 状态：提议（待审查）
- 日期：2026-10-25
- 作者：Claude
- 用户要求：在调查页旁边加一个箭头，点开就能看到 AI 在这个项目里做了什么、改了什么等等；这些内容要一直保留，不能因为上下文压缩而丢失。

## 数据从哪里来：只用永久记录，不用模型上下文

模型上下文会被压缩（ADR 0008），旧的步骤会被换成摘要或证据 ID，所以面板**完全不读上下文**，只读以下永久记录：

| 内容 | 来源 |
|---|---|
| 时间线（每个 Agent 的每一步） | 日志（只追加，不会删改） |
| 读过的文件 | 日志里的 `read_file` 调用和结果 |
| 命令与操作 | 日志里的 `run_command` / 终端调用，加上电脑操作记录（ADR 0012） |
| 结论与记忆 | 主张表和笔记表 |
| 改动 | 新增的工作区快照（见下） |

## 工作区快照（`workspace.py`）

调查开始时（根任务第一次运行之前）拍一张，结束时再拍一张，存进新表 `workspace_snapshots(task_id, phase, at, doc)`。子任务不拍，和根任务共用。

- 每个文件记录大小和修改时间；文本文件（≤ 512 KB，前 8 KB 没有空字节）还记录 sha256，并把内容存进内容寻址的证据库，这样以后能看逐行差异。
- 跳过 `.git`、`node_modules`、`.venv` 等目录（和代码证据用同一份清单），最多 20000 个文件，超出会标出"未扫完"。
- "开始"快照只拍一次：断点续跑不会覆盖它。
- 调查还在进行时，"改动"页对比的是"开始 → 现在"；结束后对比"开始 → 结束"，之后你自己再改文件，也不会算到这次调查头上。
- 逐行差异比较时忽略换行符（CRLF / LF），只有换行符不同时会单独说明，不会显示整个文件都改了。差异最多显示 2000 行。
- 在用户的游戏项目上实测：约 1100 个文件、其中 295 个文本文件，拍一次约 3 秒，对比约 0.4 秒。拍快照在后台线程里做，不阻塞调度。

**局限**：快照只能看出文件变了，看不出是谁改的。调查期间你自己或其他程序改的文件也会出现在"改动"里，面板上有这句提示。现在 Agent 没有写文件的工具（只有开启电脑操作后的终端命令或键盘输入可能改文件，这些在"命令与操作"里都有记录），所以"改动"列出来的大多是外部修改；以后开放写文件后，可以和日志里的写操作对上，标出是哪个 Agent 改的。

## 界面

- 调查页最右边有一条竖着的"◀ 工作区一览"，点开后出现 480 像素宽的面板，右上角"›"收起。默认收起。
- 五个标签页：**改动 / 时间线 / 读过的文件 / 命令与操作 / 结论与记忆**。每页上面是列表，下面是详情（参数、完整结果、差异），中间可以拖动。
- 差异着色：新增绿色、删除红色、位置行蓝色。
- 只有面板展开时才去读数据；运行中最多每 2 秒刷新一次，并且只有日志或主张有变化时才刷新；"改动"在后台线程计算，运行中最多每 10 秒算一次。

## 没有做的

- 还没有 HTTP 接口（桌面程序和后台在同一进程，直接调用）。
- 没有"撤销改动"的按钮：要恢复文件，目前请用 Git。

## 测试

`tests/daemon/test_workspace.py`（7 项）：

- 改动和逐行差异（新增、删除、修改，二进制文件只比大小）；
- 只有换行符不同时不算逐行改动；
- 结束快照固定住这次调查的改动，之后的修改不算；
- 开始快照只拍一次；
- 一次真实运行留下快照、时间线、读过的文件、命令；
- 子任务不拍快照；
- 调查页的箭头、展开、收起和各标签页内容。
