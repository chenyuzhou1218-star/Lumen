# 给负责复查的 AI 的说明

你要做的：在真实的 Lumen 窗口里，照着 `docs/review-checklist.md` 一条一条亲手试，把看到的如实写成报告。你不改代码，只找问题、报告问题。

## 规矩
- 只用真实窗口去试。不要读完代码就说"应该没问题"；看不到的就写"没法测"，并说明原因。
- 模型由用户选，你不能替用户换模型，也不能为了测试去选更贵的模型。要测花钱相关的项目，用清单里写的办法：把上限调到最小，或者用便宜的模型。
- 不碰 `D:\private\game`。不按名字结束 python 进程（用户有训练在跑）。不下载、不安装任何东西。
- 不往用户桌面上弹新窗口；Lumen 本身的窗口除外。
- API 密钥不写进报告，也不写进任何文件。

## 报告
- 放在 `D:\CodeDoctor\trials\review-<日期>-<做完的那一块>\REPORT.md`，截图放在同一个文件夹里。
- 开头写清楚：测的是哪个提交（`git log --oneline -1` 的结果）、窗口多大、浅色还是深色、用了哪个模型。
- 然后按清单的编号逐条写"通过 / 不通过 / 没法测"。不通过的写复现步骤、预期、实际，附截图。
- 最后单独列出"最严重的三个问题"。凡是花钱的问题（模型被换掉、多跑了、超出上限没停），一律排在最前面。

## 什么时候做
每当主会话说"某一大块做完并提交了"，就从那个提交开始，把整张清单从头走一遍：不只看新改的部分，旧的部分也要再试，因为改动可能把它弄坏了。
